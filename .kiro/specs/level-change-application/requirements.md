# 会員レベル変更申請システム 要件定義書

## Introduction

管理者が会員のレベル変更を申請し、申請月の翌月1日に自動的にレベル変更が実行されるシステムを構築します。現在の即座にレベル変更される仕組みから、申請・承認・実行のワークフローに変更します。

## Requirements

### Requirement 1: 会員レベル変更申請機能

**User Story:** 管理者として、会員のレベル変更を申請したい。そうすることで、計画的なレベル変更管理ができる。

#### Acceptance Criteria

1. WHEN 管理者がユーザー編集画面でレベル変更を行う THEN システムは即座にレベルを変更せず申請として保存する
2. WHEN レベル変更申請を行う THEN 管理者パスワード認証が必要である
3. WHEN レベル変更申請を行う THEN 変更理由の入力が必須である
4. WHEN レベル変更申請が成功する THEN 申請情報がDBに保存される
5. WHEN レベル変更申請が成功する THEN 申請月の翌月1日が実行予定日として設定される

### Requirement 2: 申請データ管理

**User Story:** システム管理者として、レベル変更申請の履歴を管理したい。そうすることで、申請状況を追跡できる。

#### Acceptance Criteria

1. WHEN レベル変更申請が作成される THEN 申請者、対象ユーザー、変更前レベル、変更後レベル、申請理由、申請日時、実行予定日が記録される
2. WHEN 申請が作成される THEN 申請ステータスは「pending」に設定される
3. WHEN 申請が実行される THEN 申請ステータスは「completed」に更新される
4. IF 申請がキャンセルされる THEN 申請ステータスは「cancelled」に更新される

### Requirement 3: 自動レベル変更実行

**User Story:** システムとして、申請されたレベル変更を翌月1日に自動実行したい。そうすることで、一括でレベル変更を処理できる。

#### Acceptance Criteria

1. WHEN 毎月1日の0:00になる THEN システムは実行予定日が当日のpending申請を取得する
2. WHEN pending申請が存在する THEN システムは各申請に対してレベル変更を実行する
3. WHEN レベル変更が実行される THEN 既存のuser_level_historiesテーブルにも履歴が作成される
4. WHEN レベル変更が完了する THEN 申請ステータスがcompletedに更新される
5. IF レベル変更実行中にエラーが発生する THEN エラーログが記録され、申請ステータスはerrorに設定される

### Requirement 4: 申請管理画面

**User Story:** 管理者として、レベル変更申請の一覧を確認したい。そうすることで、申請状況を把握できる。

#### Acceptance Criteria

1. WHEN 管理者が申請一覧画面にアクセスする THEN 全ての申請が表示される
2. WHEN 申請一覧を表示する THEN 申請者、対象ユーザー、変更内容、ステータス、実行予定日が表示される
3. WHEN pending申請が存在する THEN 管理者はキャンセル操作ができる
4. WHEN 申請をキャンセルする THEN 確認ダイアログが表示される

### Requirement 5: 通知機能

**User Story:** 関係者として、レベル変更申請や実行について通知を受けたい。そうすることで、変更を把握できる。

#### Acceptance Criteria

1. WHEN レベル変更申請が作成される THEN 対象ユーザーに申請通知メールが送信される
2. WHEN レベル変更が実行される THEN 対象ユーザーに変更完了通知メールが送信される
3. WHEN レベル変更実行でエラーが発生する THEN 管理者にエラー通知メールが送信される

### Requirement 6: 既存機能との互換性

**User Story:** システム利用者として、既存の機能が正常に動作し続けることを期待する。そうすることで、業務継続性が保たれる。

#### Acceptance Criteria

1. WHEN ユーザー詳細画面を表示する THEN 現在のレベルと申請中のレベル変更（あれば）が表示される
2. WHEN レベル変更申請が存在する THEN ユーザー編集画面で申請状況が表示される
3. WHEN 既存のレベル履歴機能を使用する THEN 従来通り履歴が表示される
4. WHEN インセンティブ計算を行う THEN 購入時点でのレベルに基づいて正しく計算される（既存の履歴ベース計算を維持）
